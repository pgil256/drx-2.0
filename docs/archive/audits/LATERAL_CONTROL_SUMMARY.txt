================================================================================
IMPORTANT NOTES
================================================================================

1. CONTROL LOCKING MECHANISM
   - All actuator control buttons are in self.actuator_controls list
   - When ANY movement starts, ALL buttons are disabled
   - This prevents conflicting simultaneous movements
   - Includes: lateral, horizontal, axial, leg-length buttons

2. 200ms DELAY PURPOSE
   - Gives Arduino time to process and settle
   - Prevents rapid button clicks causing queue
   - Ensures actuator has stopped moving before next command
   - Standard debounce pattern for hardware control

3. PROTOCOL vs MANUAL MODE
   - enable_actuator_controls() only works when protocol_running == False
   - During protocol execution, buttons remain disabled
   - Prevents manual intervention during automated therapy

4. CALIBRATION DEPENDENCY
   - Movement requires valid entry in config.CMarks
   - Maps angle degrees to firmware position codes
   - Missing calibration values will prevent movement
   - Hardware-specific calibration stored in kneespa.cfg

5. ARDUINO COMMAND FORMAT
   - Lateral movement: "K{position}" (e.g., "K50")
   - Position is calibrated integer, not raw angle
   - Serial communication: 9600 baud, /dev/serial0
   - Arduino processes asynchronously, sends "done" when complete

6. ERROR HANDLING
   - Out-of-bounds angles: logs warning, shows timed error, returns
   - Missing calibration: logs error message, returns
   - Both prevent movement without throwing exceptions

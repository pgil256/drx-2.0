================================================================================
EXECUTIVE FINDINGS
================================================================================

The KneeSpa application is a PyQt5-based medical device control system that
uses multiple threads to manage Arduino communication, protocol execution,
and UI updates. The analysis revealed pervasive lack of thread synchronization:

KEY ISSUES:
1. Unsynchronized flag access across threads (I2Cstatus)
2. Shared mutable state without protection (Protocol parameters)
3. TOCTOU (Time-Of-Check-Time-Of-Use) races in serial communication
4. Missing signal definitions causing runtime crashes
5. Unmanaged thread lifecycle
6. Non-atomic signal connection/disconnection operations

RISK FACTORS:
- Continuous background I/O thread reading from Arduino
- UI thread can modify protocol parameters during execution
- Reset operations depend on unreliable flag synchronization
- Serial port access can fail if connection state becomes inconsistent
- No mutex/lock protection on shared resources

BUG #2: I2Cstatus Race Condition
  Location: reset_worker.py:33-45, kneespa.py:193,1637,1643
  Impact: Reset operations hang or complete prematurely
  Fix Effort: 30 minutes

  Root Cause: Unsynchronized flag access
    Worker thread: while self.main_window.I2Cstatus == 0  # NO LOCK
    Main thread:   self.I2Cstatus = 1                     # NO LOCK

  Solution: Add threading.Lock() and protect all access

---

BUG #3: Protocol Parameter Race
  Location: protocols.py:71,732,344 and kneespa.py:689,732
  Impact: Inconsistent actuator movements, wrong parameters used
  Fix Effort: 45 minutes

  Root Cause: No synchronization on shared state
    UI Thread:     self.worker.use_pulse = current_state  # Write
    Worker Thread: while self.use_pulse:                  # Read

  Solution: Add threading.Lock() around all parameter access

---

BUG #4: Arduino Send TOCTOU Race
  Location: arduino.py:438-465
  Impact: Crash when sending commands during disconnect
  Fix Effort: 20 minutes

  Root Cause: Lock released after check but before use
    with self._lock:
        if not self.connected:  # Check
            # ... lock released here ...
    self.serial_com.write()     # Use (port may be closed)

  Solution: Expand lock scope to cover entire send operation

---

BUG #5: Connection State Race
  Location: arduino.py:218,325,350
  Impact: Inconsistent connection state, potential crashes
  Fix Effort: 15 minutes

  Root Cause: Flag updates without synchronization
    self.connected = True   # No lock
    self.connected = False  # No lock

  Solution: Protect all writes with self._lock
